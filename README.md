# Warsaw flat monitor

Мониторит Otodom и OLX, шлёт новые подходящие объявления в Telegram.
Крутится бесплатно на GitHub Actions каждые 15 минут.

**Текущие фильтры** (меняются в `config.py`):
Wola / Żoliborz / Śródmieście · аренда · до 6000 zł (без чинша) · 2+ комнаты · от 50 м² · только собственники.

---

## Что и в каком порядке сделать

### Шаг 1. Создать Telegram-бота (2 минуты)
1. В Telegram напиши **@BotFather** → команда `/newbot`.
2. Задай имя и username бота. BotFather пришлёт **токен** вида
   `8123456789:AAH...` — это `TELEGRAM_BOT_TOKEN`.
3. Найди своего бота по username и нажми **Start** (иначе он не сможет тебе писать).

### Шаг 2. Узнать свой chat_id (1 минута)
1. Напиши боту **@userinfobot** — он ответит твоим числовым `Id`.
2. Это и есть `TELEGRAM_CHAT_ID`.

### Шаг 3. Создать репозиторий на GitHub
1. github.com → **New repository** → назови, например `warsaw-flat-monitor`.
   Можно **Private** — Actions работает и в приватных.
2. Загрузи туда все файлы из этой папки (кнопка *Add file → Upload files*,
   либо через `git push`). Структура должна остаться такой же, включая
   папку `.github/workflows/`.

### Шаг 4. Прописать секреты
В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
Добавь два:
- `TELEGRAM_BOT_TOKEN` — токен из шага 1
- `TELEGRAM_CHAT_ID` — id из шага 2

### Шаг 5. Включить и проверить Actions
1. Вкладка **Actions** → если просит — нажми *I understand… enable workflows*.
2. Слева выбери **Warsaw flat monitor** → кнопка **Run workflow** (ручной запуск).
3. Открой лог запуска. Что ждать:
   - `Всего собрано карточек: N` — если N > 0, парсинг работает.
   - Первый запуск отправит пачку текущих объявлений (база `seen.json` пуста).
     Дальше будут приходить только новые.

Готово. Дальше воркфлоу сам запускается каждые 15 минут.

## Как менять фильтры
Всё в `config.py`. Самое частое:
- `PRICE_MAX`, `AREA_MIN`, `ROOMS_MIN` — цифры.
- `OWNERS_ONLY = False` — включить объявления агентств (тот самый переключатель).
- `OTODOM_DISTRICTS` — список слагов района из URL Otodom.

После правки просто закоммить `config.py` — следующий запуск подхватит.

## Если что-то не пришло / парсер пустой

Otodom и OLX периодически меняют вёрстку и внутреннюю структуру JSON —
это нормально для скраперов. Признак: в логе `Всего собрано карточек: 0`
или `__NEXT_DATA__ не найден`.

Что проверить в первую очередь:
1. **Слаги районов Otodom.** Открой в браузере
   `https://www.otodom.pl`, выставь фильтры руками, посмотри, как называется
   район в адресной строке (`.../warszawa/<slug>`), и впиши в `OTODOM_DISTRICTS`.
2. **Ключи полей.** Структура JSON могла сдвинуться — парсер написан
   устойчиво (рекурсивный поиск), но названия полей цены/площади могли
   поменяться.

Локальная отладка без спама в Telegram:
```bash
pip install -r requirements.txt
python monitor.py --dry-run      # печатает найденное в консоль, ничего не шлёт
python test_logic.py             # оффлайн-проверка логики на мок-данных
```

Именно этот момент удобнее чинить в **Claude Code**: он видит файлы, сам
запускает `--dry-run` против живых страниц и правит парсер по факту.

## Файлы
- `config.py` — параметры поиска (правишь в основном только его).
- `monitor.py` — вся логика.
- `test_logic.py` — оффлайн-тесты.
- `seen.json` — база отправленных id (обновляется автоматически).
- `.github/workflows/monitor.yml` — расписание запуска.
